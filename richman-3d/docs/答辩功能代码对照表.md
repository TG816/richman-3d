# Richman 3D 功能与代码答辩对照表

适用项目：`TG816/richman-3d`。本文按现有代码整理，可在答辩时按函数名搜索定位。所有路径以含 `package.json` 的内层项目目录为起点；负责人表示模块分工，不代表每段代码均由该成员独立完成。

## 一、开场说明

项目是一款基于浏览器的多人三维大富翁游戏。前端使用 Three.js 渲染，Vite 构建；后端采用 Node.js、Express 和 Socket.IO。服务器统一处理回合、资产和卡牌规则，客户端负责输入、界面和动画。实时语音使用 WebRTC，消息协商通过 Socket.IO，必要时经 TURN 中继。

本项目不是纯前端，也不包含 AI 对手。现有一个 40 格城市棋盘，支持 2–6 人房间对局。规则为项目自定义组合，例如“再次落到自己的地产才可升级一级”，不宣称完整复刻某一版官方大富翁。

## 三、关键流程的现场讲法

### 1. “升级为什么不能连续点？”

打开 `engine.js`，依次看 `resolveTile → build → finishAction`。再次落到自有地产才进入 upgrade；build 校验当前玩家和 pending 地块；成功后清空待处理机会。第二次请求已经不在 upgrade 阶段，所以不会再扣钱或升房。

### 2. “骰子点数是动画决定的吗？”

不是。服务端 roll 生成点数并更新规则；客户端收到 dice 事件，把相同点数传给 Dice.roll，计算最终朝向。动画只是显示。数字提示也使用同一个事件，避免三维和文字分别随机。

### 3. “为什么改了静音按钮仍曾听到声音？”

当时 UI 保存的是玩家 ID，但接收音频按 Socket ID 管理，房间快照缺少对应字段。修复 roomState 后，通过玩家 ID 与连接 ID 映射应用到实际 audio，并增加重连场景测试。

### 4. “存档是不是只保存钱和位置？”

还保存地产、回合阶段、待处理选择、持卡来源、结算及牌库状态。新存档通过 saveSnapshot 额外保存牌序，而发给客户端的 snapshot 不包含完整牌序。

### 5. “项目是不是不需要网络？”

不是。模型、贴图和游戏音效主要由代码生成，背景音乐是本地 MP3；但多人游戏需要连接后端，跨网络语音使用 STUN/TURN。无需远程下载模型，不等于运行时零外网依赖。

### 6. “手机为什么不能开麦？”

浏览器麦克风采集需要安全上下文和用户许可。电脑 localhost 有本机例外，手机访问电脑的普通 HTTP 局域网 IP 不具有同样条件。应通过有效 HTTPS 测试，不把该报错说成硬件损坏。
